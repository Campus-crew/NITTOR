# Система Агентов - Архитектура и Документация

## Обзор

Система агентов предназначена для создания и управления сценариями видеогенерации с контекстным пониманием проекта. Каждый проект может иметь сценарий, который работает как TODO-лист этапов производства.

## Основные Концепции

### 1. Сценарий (Scenario)
- **Назначение**: Структурированный план создания видео контента
- **Формат**: TODO-лист с этапами (ScenarioStep)
- **Привязка**: Один сценарий на проект
- **Генерация**: Создается на основе промпта пользователя при создании проекта

### 2. Этапы Сценария (ScenarioStep)
- **Структура**: Каждый этап имеет описание, порядок выполнения, статус
- **Статусы**: pending, in_progress, completed, skipped
- **Контекст**: Каждый этап может содержать дополнительные инструкции для генерации

### 3. Контекстная Генерация
- **Флаг контекста**: При генерации можно включить "учитывать контекст проекта"
- **Использование фреймов**: Система анализирует уже созданные файлы проекта
- **Этап сценария**: Добавляется к промпту пользователя для контекстной генерации

## Архитектура Данных

### Модели

```
Project (существующая)
├── Scenario (новая)
    ├── prompt: str - исходный промпт для создания сценария
    ├── generated_at: datetime - когда был создан сценарий
    ├── is_active: bool - активен ли сценарий
    └── steps: List[ScenarioStep] - этапы сценария

ScenarioStep (новая)
├── title: str - название этапа
├── description: str - описание этапа
├── order_index: int - порядок выполнения
├── status: enum - статус выполнения
├── context_prompt: str - дополнительный контекст для генерации
├── completed_at: datetime - когда был завершен
└── generated_files: List[ProjectFile] - файлы созданные на этом этапе
```

### Связи
- Project 1:1 Scenario
- Scenario 1:N ScenarioStep
- ScenarioStep 1:N ProjectFile (через связующую таблицу)

## Workflow Генерации

### 1. Создание Проекта с Сценарием
```
POST /projects/
{
  "name": "My Video Project",
  "description": "...",
  "scenario_prompt": "Создай сценарий для рекламного ролика о кофе" // опционально
}
```

### 2. Генерация с Контекстом
```
POST /generation/generate
{
  "prompt": "Создай сцену с чашкой кофе",
  "project_id": 123,
  "use_project_context": true, // флаг использования контекста
  "scenario_step_id": 456 // какой этап сценария выполняем
}
```

### 3. Отметка Этапа как Выполненного
```
PUT /projects/{project_id}/scenario/steps/{step_id}/complete
{
  "generated_file_ids": [789, 790] // файлы созданные на этом этапе
}
```

## API Endpoints

### Сценарии
- `GET /projects/{id}/scenario` - Получить сценарий проекта
- `POST /projects/{id}/scenario` - Создать сценарий для проекта
- `PUT /projects/{id}/scenario` - Обновить сценарий
- `DELETE /projects/{id}/scenario` - Удалить сценарий

### Этапы Сценария
- `GET /projects/{id}/scenario/steps` - Получить все этапы
- `POST /projects/{id}/scenario/steps` - Создать новый этап
- `PUT /projects/{id}/scenario/steps/{step_id}` - Обновить этап
- `PUT /projects/{id}/scenario/steps/{step_id}/complete` - Отметить как выполненный
- `PUT /projects/{id}/scenario/steps/{step_id}/status` - Изменить статус
- `DELETE /projects/{id}/scenario/steps/{step_id}` - Удалить этап

### Контекстная Генерация
- `POST /generation/generate-with-context` - Генерация с учетом контекста проекта
- `GET /projects/{id}/context` - Получить контекст проекта для генерации

## Логика Контекстной Генерации

### 1. Сбор Контекста
При включенном флаге `use_project_context`:
- Анализируются все файлы проекта
- Извлекаются ключевые фреймы из видео
- Анализируются промпты предыдущих генераций
- Учитывается текущий этап сценария

### 2. Формирование Промпта
```
Финальный промпт = 
  Промпт пользователя + 
  Контекст текущего этапа сценария +
  Описание стиля из предыдущих файлов +
  Инструкции по консистентности
```

### 3. Отслеживание Прогресса
- Каждый созданный файл привязывается к этапу сценария
- Статистика выполнения сценария
- Возможность вернуться к предыдущим этапам

## Преимущества Системы

1. **Структурированность**: Четкий план создания контента
2. **Консистентность**: Учет контекста предыдущих генераций
3. **Отслеживание**: Понимание прогресса проекта
4. **Гибкость**: Возможность изменять сценарий в процессе
5. **Контекст**: Умная генерация с учетом уже созданного контента

## Примеры Использования

### 1. Создание Проекта с Автоматическим Сценарием
```bash
curl -X POST "/projects/" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "name": "Coffee Commercial",
    "description": "30-second coffee advertisement",
    "scenario_prompt": "Create a scenario for a 30-second coffee commercial showing morning routine"
  }'
```

### 2. Генерация с Контекстом
```bash
curl -X POST "/projects/123/generate-prompt" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "prompt": "Show person drinking coffee with satisfaction",
    "use_project_context": true,
    "scenario_step_id": 456
  }'
```

### 3. Отметка Этапа как Выполненного
```bash
curl -X PUT "/projects/123/scenario/steps/456/complete" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "generated_file_ids": [789, 790],
    "generation_notes": "Successfully created morning scene with consistent lighting",
    "actual_duration": 1800
  }'
```

## Интеграция с Существующей Системой

### Обратная Совместимость
- Все существующие проекты продолжают работать без изменений
- Сценарии создаются опционально при создании проекта
- Генерация без контекста работает как раньше

### Миграция Данных
- Новые таблицы: `scenarios`, `scenario_steps`, `scenario_step_files`
- Связи через foreign keys с существующими таблицами
- Soft delete для всех сущностей

### Производительность
- Индексы на часто используемые поля
- Lazy loading для связанных данных
- Кэширование контекста проекта

## Техническая Реализация

### Архитектурные Решения
- **Модульность**: Система агентов изолирована от основной логики
- **Расширяемость**: Легко добавлять новые типы этапов и статусов
- **Производительность**: Оптимизированные запросы с joinedload
- **Безопасность**: Проверка прав доступа на всех уровнях

### Паттерны Проектирования
- **Repository Pattern**: CRUD операции в отдельных сервисах
- **Service Layer**: Бизнес-логика в сервисных классах
- **Dependency Injection**: FastAPI зависимости для аутентификации
- **Strategy Pattern**: Различные стратегии построения контекста

### Обработка Ошибок
- Валидация входных данных через Pydantic
- Проверка зависимостей между этапами
- Транзакционность операций с базой данных
- Информативные сообщения об ошибках
